element plus的命名空间

解析

element plus使用命名空间去统一了样式名称前缀。命名空间功能的实现集中在useNamespace这个钩子上，下面将会对这个钩子进行解析，在它所暴露的方法上还能发现element plus对于BEM规范的实现。

首先先看它的使用。它接收两个参数，一个必传参数block（组件主体名称），一个可选参数namespaceOverrides

简单来说这个钩子优先使用显式传入的 namespaceOverrides；否则通过 inject(namespaceContextKey) 获取祖先 ConfigProvider 提供的 namespace；如果没有注入值，使用默认值 el。然后钩子通过传入block锚定目标组件，暴露出若干方法并遵循BEM规范去拼接class名称。

flowchart LR
    A["ConfigProvider<br/>namespace='my'"] --> B["运行时 useNamespace"]
    B --> C["my-button"]
    B --> D["--my-button-bg-color"]

    E["Sass 构建配置<br/>$namespace: 'my'"] --> F[".my-button"]
    E --> G["var(--my-button-bg-color)"]

    C -. "class 匹配" .-> F
    D -. "CSS 变量匹配" .-> G

它和 CSS Modules、scoped 有什么区别

他并非限定某一个组件作用域，而是全局的，使用命名空间更多的是将组件库命名与整个项目中的其他模块进行隔离，同时规范命名。
